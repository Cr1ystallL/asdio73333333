# 👛 Архитектура системы виртуальных кошельков (Wallet System)

## 1. Структура сущности кошелька (Wallet Entity)

Каждый пользователь (клиппер или рекламодатель) при регистрации получает привязанную сущность `wallet`:
* **`id`:** UUID v4 уникальный идентификатор кошелька.
* **`user_id`:** Ссылка на пользователя.
* **`currency`:** Базовая валюта (строго `RUB`).
* **`is_frozen`:** Флаг экстренной заморозки кошелька службой безопасности (при подозрении на мошенничество).

---

## 2. Разделение типов балансов внутри кошелька
1. **Available Balance (Доступный баланс):** Средства, свободные для немедленного вывода на банковскую карту через СБП или использования для запуска новых кампаний.
2. **Pending Balance (Холд-баланс):** Зарезервированные системой средства, находящиеся в процессе 72-часовой валидации просмотров антифродом.
3. **Escrow Locked (Эскроу-резерв):** Средства рекламодателя, выделенные под активные кампании и заблокированные от вывода до завершения срока кампании.

---

## 3. Расчет балансов в реальном времени
Баланс кошелька не является изменяемым числом в строке пользователя. Он вычисляется как проекция проводок в таблице `ledger_entries`:
```sql
SELECT 
  COALESCE(SUM(CASE WHEN direction = 'CREDIT' THEN amount_cents ELSE -amount_cents END), 0) AS balance_cents
FROM ledger_entries
WHERE account_id = 'wallet_uuid' AND state = 'SETTLED';
```
