# Мониторинг, Метрики и Алертинг (Monitoring & Alerting)

Документ регламентирует инструменты сбора технических и бизнес-метрик, трекинга ошибок и правила оповещения дежурной команды.

---

## 1. Стек наблюдаемости (Observability Stack)

| Компонент | Инструмент | Назначение |
| :--- | :--- | :--- |
| **Метрики** | **Prometheus + Grafana** | Системные метрики (CPU, RAM, Event Loop lag, RPS) и бизнес-метрики (просмотры в минуту, расход эскроу, размер очередей BullMQ) |
| **Ошибки и трассировка** | **Sentry** | Автоматический перехват runtime-исключений на бэкенде и фронтенде с полным stacktrace и контекстом пользователя |
| **Алертинг** | **Grafana Alerting + Telegram Bot** | Мгновенная доставка оповещений в приватный канал дежурных инженеров |
| **Uptime мониторинг** | **Uptime Kuma / BetterStack** | Проверка доступности внешних эндпоинтов раз в 60 секунд из 3 независимых гео-точек |

---

## 2. Градация алертов (Severity Levels)

1. **P1 — CRITICAL (Немедленное пробуждение инженера в любое время суток)**:
   - Расхождение в ночном аудите Ledger ($\text{Mismatch} > 0$).
   - Недоступность API платежей / шлюза выплат СБП более 3 минут подряд.
   - 5xx HTTP ошибки бэкенда превышают 2% от общего трафика.
2. **P2 — WARNING (Реакция в течение рабочего дня / 2 часов)**:
   - Использование квоты YouTube Data API превысило 80% до наступления полуночи.
   - Размер очереди `tracking-sync` превысил 5 000 задач.
3. **P3 — INFO**:
   - Запуск крупной кампании с бюджетом свыше 500 000 ₽.
