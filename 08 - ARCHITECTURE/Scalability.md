# Масштабируемость и Высокая Доступность (Scalability & HA)

Документ описывает стратегию горизонтального и вертикального масштабирования платформы Konveer при росте аудитории до 100 000+ авторов и сотен миллионов просмотров в месяц.

---

## 1. Горизонтальное масштабирование сервисов (Stateless Backend)

- Серверные экземпляры бэкенда спроектированы как **полностью Stateless**:
  - Пользовательские сессии не сохраняются в оперативной памяти процесса (хранятся в подписанных JWT и Redis).
  - Любой HTTP-запрос может быть обработан любым инстансом бэкенда за балансировщиком нагрузки Nginx / Cloudflare.
- Автомасштабирование (HPA):
  - При превышении нагрузки CPU > 70% автоматически поднимаются дополнительные контейнеры бэкенда.

---

## 2. Кэширование и оптимизация базы данных

```mermaid
flowchart TD
    Client[Клиентский запрос: Каталог кампаний] --> Redis{Проверка кэша Redis}
    Redis -->|Кэш валиден (HIT)| Return[Мгновенный ответ: 2 мс]
    Redis -->|Промах (MISS)| DB[(PostgreSQL Read Replica)]
    DB --> WriteCache[Запись в Redis с TTL=60 сек]
    WriteCache --> Return
```

- **Кэширование каталога кампаний**: Список активных кампаний кэшируется в Redis на 60 секунд. Инвалидация происходит точечно при создании или закрытии кампании через Pub/Sub шину.
- **Пакетная обработка синхронизации просмотров**: Запросы к YouTube/VK пакетируются по 50 видео, экономя 98% сетевых накладных расходов.
