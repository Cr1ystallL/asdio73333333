# 🔌 Матрица реализуемости интеграций с социальными сетями

Критически важный документ технического анализа: что в действительности возможно получать через официальные API без авторизации владельца аккаунта, а что требует альтернативных инженерных решений.

---

## 1. Сравнительная матрица возможностей API

| Платформа | Метод получения статистики | Требуется ли OAuth владельца канала? | Доступные метрики | Ограничения и лимиты | Статус для MVP |
| :--- | :--- | :---: | :--- | :--- | :---: |
| **YouTube Shorts** | `YouTube Data API v3` (`videos.list`) | ❌ **НЕТ** (Достаточно стандартного API Key) | `viewCount`, `likeCount`, `commentCount`, дата публикации, название, описание, теги | 10 000 квот/день бесплатно (до 50 ID за 1 квоту = 500 000 видео/сутки) | 🟢 **Основной канал MVP** |
| **VK Клипы** | `VK API` (`video.get`, `wall.getById`) | ❌ **НЕТ** (Достаточно Service Access Token приложения) | `views`, `likes`, `reposts`, дата публикации, описание | До 20 запросов в секунду. Отдает публичную статистику клипов | 🟢 **Основной канал MVP** |
| **TikTok** | `Display API` / Web Data Extraction | ⚠️ **ДА для официального API** / ❌ НЕТ для скрапера метаданных | `play_count`, `digg_count`, `share_count` | Официальный API требует модерации приложения в TikTok for Developers и OAuth юзера. Web-скрапинг требует резидентных прокси | 🟡 **Stage 4 (Полуавтомат / Скрапер)** |
| **Instagram Reels** | `Instagram Graph API` | 🛑 **ДА** (Только Creator/Business аккаунт через Facebook Login) | `views`, `reach`, `likes` | Статистику произвольного чужого Reels по ссылке через официальный API получить **НЕВОЗМОЖНО** без OAuth токена автора | 🔴 **Stage 6 (Только через OAuth или ручную модерацию)** |

---

## 2. Архитектурный вывод для команды разработки

> [!WARNING]
> **Недопустимое заблуждение:** Предполагать, что любая соцсеть по публичной ссылке позволяет через официальный бесплатный API вытащить данные.  
> **Инженерный вердикт:** Первая версия (MVP) должна строиться строго на **YouTube Shorts + VK Клипы**, где API стабилен, легален, не блокирует IP серверов и не требует авторизации авторов через соцсети. Это сокращает срок разработки MVP на 2 месяца и снижает риски поломки парсеров до нуля.
