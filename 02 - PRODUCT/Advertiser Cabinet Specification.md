# 💻 Полная спецификация кабинета рекламодателя (Web Portal)

> [!IMPORTANT]
> Настоящий документ представляет собой детальное техническое задание для B2B-портала заказчика (бренды, стримеры, агентства, селлеры маркетплейсов). Каждый из 12 разделов расписан по стандарту промышленного проектирования.

---

## 1. Раздел: Dashboard (Сводный экран заказчика)
* **1.1. Назначение:** Главная аналитическая витрина аккаунта; агрегирует сквозную эффективность всех запущенных кампаний, статус освоения бюджетов и оперативные уведомления.
* **1.2. Элементы интерфейса:**
  * Верхняя панель метрик:
    * Совокупные подтвержденные просмотры (например: `3 420 000`).
    * Средний эффективный CPM (`104.2 ₽`).
    * Активных кампаний в работе (`4`).
    * Доступный свободный баланс депозита (`62 400 ₽`).
  * График динамики охвата (Recharts): график прироста просмотров по дням с фильтрацией по платформам (YouTube Shorts / VK Клипы).
  * Таблица «Топ-5 лучших роликов недели»: Превью, автор, площадка, число просмотров, ссылка на видео.
  * Блок быстрых действий: Кнопка «+ Создать кампанию», кнопка «Пополнить баланс».
* **1.3. Доступные действия:** Переключение диапазонов дат (7д, 30д, квартал), скачивание сводного PDF-отчета, быстрый переход к конкретной кампании.
* **1.4. Логика работы:** Запрос `GET /api/v1/advertiser/dashboard-stats`. Данные кэшируются на 5 минут в Redis.
* **1.5. Состояния:** `Loading` (скелетоны графиков), `Empty` (для новых заказчиков с кнопкой «Запустить первую кампанию»), `Populated`.
* **1.6. Ошибки:** Ошибка авторизации (редирект на `/login`), сетевой таймаут.
* **1.7. Ограничения:** Доступно только пользователям с ролью `ADVERTISER`.
* **1.8. Взаимодействие:** Модуль кампаний, аналитика, биллинг.

## 2. Раздел: Создание кампаний (Create Campaign Wizard)
* **2.1. Назначение:** 4-шаговый мастер настройки и запуска новой рекламной кампании.
* **2.2. Элементы интерфейса:**
  * Шаг 1 (Общая информация): Название, выбор категории, цель (Охват / Трафик на сайт / Подписчики в TG / Заказы на WB).
  * Шаг 2 (Материалы и ТЗ): Ссылка на облако исходников (Яндекс Диск / S3), текст брифа для клипперов, обязательные хэштеги, ссылка с UTM-метками для закрепленного комментария.
  * Шаг 3 (Экономика): Выбор модели (CPM за просмотры / Лидерборд недели), ставка CPM (с подсказкой рынка: 100–120 ₽), потолок выплаты на 1 видео (Cap), антимонопольный лимит на 1 автора (например, не более 20% пула), общий бюджет кампании (мин. 10 000 ₽).
  * Шаг 4 (Маркировка и Оплата): Реквизиты юрлица для ОРД (ИНН, наименование), сводная смета (Пул клипперов 80% + Комиссия платформы 20%), выбор способа оплаты (Карта / СБП / Счет для юрлица).
* **2.3. Доступные действия:** Переход между шагами, сохранение черновика (Save Draft), оплата и запуск.
* **2.4. Логика работы:** Атомарное создание сущности `campaign` со статусом `PENDING_PAYMENT`. При успешном платеже — перевод в `ACTIVE` и резервирование эскроу-пула в Ledger.
* **2.5. Состояния:** `Draft`, `Validating Steps`, `Payment Processing`, `Success Launched`.
* **2.6. Ошибки:** Недопустимая ссылка на облако (проверка доступности папки), бюджет меньше минимального порога.
* **2.7. Ограничения:** Запрещены к созданию кампании запрещенных тематик (гемблинг, МФО, адалт).
* **2.8. Взаимодействие:** Модуль эквайринга, ОРД интеграция, Ledger, S3.

## 3. Раздел: Редактирование кампаний (Edit Campaign)
* **3.1. Назначение:** Корректировка параметров действующей или приостановленной кампании.
* **3.2. Элементы интерфейса:** Форма редактирования описания ТЗ, добавление новых ссылок на свежие исходники, изменение списка стоп-слов, увеличение общего бюджета (долив депозита).
* **3.3. Доступные действия:** Изменение текстовых полей, пополнение пула, временная пауза (`PAUSE`), возобновление (`RESUME`).
* **3.4. Логика работы:** Запрещено изменять ставку CPM в меньшую сторону для уже запущенной кампании (защита клипперов). Ставку можно только повышать.
* **3.5. Состояния:** `Active Editable`, `Paused`.
* **3.6. Ошибки:** Попытка снизить бюджет ниже суммы уже принятых обязательств перед клипперами.
* **3.7. Ограничения:** Кампании со статусом `COMPLETED` редактированию не подлежат.
* **3.8. Взаимодействие:** Модуль кампаний, Ledger.

## 4. Раздел: Исходные материалы (Source Assets Management)
* **4.1. Назначение:** Управление медиа-файлами кампании, таймкодами и подсказками для монтажеров.
* **4.2. Элементы интерфейса:**
  * Файловый менеджер: список загруженных видеофайлов, аудиодорожек, логотипов и оверлеев.
  * Блок разметки таймкодов: текстовая таблица с подсказками от редактора бренда: *«04:12 – 04:45 — Шок-контент про цены»*, *«12:10 – 12:40 — Смешная шутка»*.
  * Кнопка прямой загрузки файлов до 5 ГБ в защищенный S3 бакет платформы.
* **4.3. Доступные действия:** Загрузка файлов, удаление устаревших исходников, добавление текстовых комментариев к файлам.
* **4.4. Логика работы:** Генерация `Presigned PUT URL` для прямой загрузки в Selectel S3 в обход бэкенда.
* **4.5. Состояния:** `Uploading (Progress bar %)`, `Ready`, `Error`.
* **4.6. Ошибки:** Превышение дисковой квоты тарифа, неподдерживаемый формат файла (только MP4, MOV, PNG, MP3).
* **4.7. Ограничения:** Максимальный размер одного файла: 5 ГБ.
* **4.8. Взаимодействие:** Selectel S3 API, CDN раздача.

## 5. Раздел: Правила публикации (Brand Safety & Guidelines)
* **5.1. Назначение:** Формализация критериев качества и юридических требований бренда к контенту.
* **5.2. Элементы интерфейса:**
  * Список стоп-слов (чипсы с возможностью добавления и удаления).
  * Чекбоксы ограничений: `[Запрет нецензурной лексики]`, `[Запрет упоминания конкурентов]`, `[Запрет черного юмора]`.
  * Требования к оформлению: логотип бренда в правом верхнем углу (PNG файл оверлея), читаемые субтитры.
* **5.3. Доступные действия:** Сохранение шаблона правил для повторного использования в будущих кампаниях.
* **5.4. Логика работы:** Сохраненные правила автоматически транслируются в карточку кампании внутри Telegram Mini App клиппера.
* **5.5. Состояния:** `Saved`, `Modified`.
* **5.6. Ошибки:** Противоречащие друг другу правила.
* **5.7. Ограничения:** Текст правил не более 5 000 символов.
* **5.8. Взаимодействие:** Модуль модерации и арбитража.

## 6. Раздел: Финансирование (Billing & Deposit Pay-In)
* **6.1. Назначение:** Управление денежным счетом рекламодателя, пополнение депозита и выбор платежных шлюзов.
* **6.2. Элементы интерфейса:**
  * Плашка текущего баланса: `Доступно: 62 400 ₽`, `Заблокировано в кампаниях: 180 000 ₽`.
  * Форма пополнения: выбор суммы (быстрые кнопки: 50k, 100k, 300k, 500k ₽).
  * Способы оплаты:
    * Для юрлиц и ИП: Безналичный счет (автогенерация PDF-счета с факсимиле).
    * Для физлиц: Банковская карта РФ, СБП через ЮKassa.
* **6.3. Доступные действия:** Выставление счета, онлайн-оплата, запрос возврата остатка депозита.
* **6.4. Логика работы:** Интеграция с эквайрингом ЮKassa (Webhook) и банковским API Т-Бизнеса (авто-проверка входящих платежек).
* **6.5. Состояния:** `Awaiting Payment`, `Payment Successful`, `Invoice Generated`.
* **6.6. Ошибки:** Отказ банка-эмитента (3D-Secure error), ошибка распознавания реквизитов.
* **6.7. Ограничения:** Минимальная сумма пополнения: 10 000 ₽.
* **6.8. Взаимодействие:** ЮKassa, Т-Банк, Ledger.

## 7. Раздел: Управление бюджетами (Budget Allocation & Cap Management)
* **7.1. Назначение:** Тонкая настройка распределения средств между кампаниями и авторами.
* **7.2. Элементы интерфейса:**
  * Слайдер лимита на одно видео (`Cap per video`: от 1 000 до 25 000 ₽).
  * Настройка суточного лимита открутки (Daily Payout Limit) во избежание резкого исчерпания пула.
  * Кнопка «Досрочно остановить кампанию и вернуть остаток».
* **7.3. Доступные действия:** Изменение лимитов, остановка кампании, перевод средств между кампаниями.
* **7.4. Логика работы:** При изменении лимита воркер пересчитывает максимальные обязательства пула в транзакции PostgreSQL.
* **7.5. Состояния:** `Limits Applied`.
* **7.6. Ошибки:** Попытка поставить Cap меньше текущего начисленного вознаграждения лидеру кампании.
* **7.7. Ограничения:** Суточный лимит не может быть меньше 5 000 ₽.
* **7.8. Взаимодействие:** Ledger, модуль кампаний.

## 8. Раздел: Аналитика (Campaign Analytics & Performance)
* **8.1. Назначение:** Глубокая маркетинговая аналитика эффективности рекламного размещения.
* **8.2. Элементы интерфейса:**
  * График совокупного охвата с разделением по площадкам (Shorts vs VK).
  * Воронка конверсии: Просмотры $\rightarrow$ Клики по ссылке в закрепленном комменте $\rightarrow$ Переходы на сайт / в Telegram-бот.
  * Аналитика стоимости клика (CPC) и стоимости тысячи показов (Effective CPM).
  * Тепловая карта пиковой активности клипперов (время выхода публикаций).
* **8.3. Доступные действия:** Фильтрация по кампаниям, экспорт аналитического отчета в формате CSV / XLSX.
* **8.4. Логика работы:** Агрегация логов просмотров и данных сервиса сокращения ссылок платформы с UTM-трекингом.
* **8.5. Состояния:** `Generating Report`, `Data Ready`.
* **8.6. Ошибки:** Недостаточно данных для построения среза (кампания запущена менее 24 ч назад).
* **8.7. Ограничения:** Исторические данные доступны за последние 12 месяцев.
* **8.8. Взаимодействие:** PostgreSQL Timescale / Analytics DB, сервис UTM-редиректов.

## 9. Раздел: Статистика публикаций (Submissions Table & Moderation)
* **9.1. Назначение:** Оперативный контроль всех созданных авторами видеороликов с возможностью мотивированного отклонения.
* **9.2. Элементы интерфейса:**
  * Таблица сабмитов:
    * Превью видео + встроенный плеер.
    * Дата публикации и прямая ссылка на YouTube/VK.
    * Текущие просмотры, лайки, комментарии, показатель ER.
    * Начисленная сумма клипперу.
    * Статус проверки: `В процессе (48 ч)`, `Одобрено`, `Отклонено`.
  * Кнопка быстрого действия: `[ Отклонить ролик ]` (активна в течение 24 часов с момента сабмита).
* **9.3. Доступные действия:** Просмотр ролика прямо в кабинете, мотивированное отклонение с выбором причины, экспорт списка ссылок.
* **9.4. Логика работы:**
  * Если заказчик нажимает «Отклонить», открывается модальное окно с выбором регламентной причины:
    1. *Отсутствует обязательная ссылка в закрепленном комментарии*.
    2. *Использованы запрещенные стоп-слова / мат*.
    3. *Ролик не содержит предоставленных материалов*.
  * При подтверждении отклонения ролик снимается с начисления, зарезервированные деньги возвращаются в свободный пул кампании, клиппер получает пуш-уведомление с причиной.
* **9.5. Состояния:** `Under Review`, `Approved`, `Rejected by Advertiser`, `Disputed`.
* **9.6. Ошибки:** Попытка отклонить ролик по истечении 24-часового окна (действие блокируется, ролик уходит на авто-одобрение).
* **9.7. Ограничения:** Рекламодатель не может отклонить ролик по субъективным причинам («мне не нравится голос»), если ТЗ соблюдено.
* **9.8. Взаимодействие:** Антифрод-модуль, система апелляций, Telegram Bot.

## 10. Раздел: Управление клипперами (Creator CRM & Whitelists)
* **10.1. Назначение:** Инструмент формирования пула доверенных и избранных авторов контента.
* **10.2. Элементы интерфейса:**
  * Белый список (White List): список топ-клипперов, чьи ролики стабильно приносят максимальный охват (возможность начислять им персональные бонусы).
  * Черный список (Black List): блокировка недобросовестных авторов от участия в кампаниях конкретного рекламодателя.
* **10.3. Доступные действия:** Добавление клиппера в Black/White list по его ID, отправка персонального оффера.
* **10.4. Логика работы:** При проверке сабмита бэкенд проверяет: `IF clipper_id IN advertiser_blacklist THEN REJECT`.
* **10.5. Состояния:** `List view`, `Empty`.
* **10.6. Ошибки:** Попытка заблокировать клиппера во время открытого спора в арбитраже.
* **10.7. Ограничения:** До 500 авторов в черном списке.
* **10.8. Взаимодействие:** Модуль сабмитов, система репутации.

## 11. Раздел: Финансовая история (Financial History & Invoices/Acts)
* **11.1. Назначение:** Бухгалтерский архив для юридических лиц: счета, УПД, акты сверок, выписки движения средств.
* **11.2. Элементы интерфейса:**
  * Список закрывающих документов за каждый отчетный месяц.
  * Кнопки скачивания: PDF с синей печатью, отправка по ЭДО (Диадок / СБИС).
  * Детализация списаний: дата, кампания, списано на клипперов, комиссия сервиса 20%.
* **11.3. Доступные действия:** Скачивание актов, подписание по ЭДО, заказ акта сверки за произвольный период.
* **11.4. Логика работы:** В последний день месяца система автоматически генерирует УПД на сумму фактически оказанных услуг (комиссии платформы) и отчет агента по выплатам клипперам.
* **11.5. Состояния:** `Generated`, `Signed via EDO`, `Pending Signature`.
* **11.6. Ошибки:** Не заполнены реквизиты компании (блокировка формирования документов с предупреждением).
* **11.7. Ограничения:** Документы формируются только для пользователей со статусом Юрлицо / ИП.
* **11.8. Взаимодействие:** 1С, Диадок API, Ledger.

---

## 12. Раздел: Настройки и ОРД (Account Settings & Legal Credentials)
* **12.1. Назначение:** Управление профилем компании, реквизитами для маркировки рекламы по 347-ФЗ, интеграциями и безопасностью.
* **12.2. Элементы интерфейса:**
  * Карточка организации: ИНН, КПП, ОГРН, Юридический адрес, Банковские реквизиты (автозаполнение по ИНН через DaData).
  * Блок маркировки рекламы (ОРД):
    * Выбор оператора: ОРД-А (Амбердата) / ОРД VK.
    * Статус передачи договоров в ЕРИР.
  * Безопасность: Смена пароля, подключение двухфакторной аутентификации 2FA (TOTP), управление API-ключами.
  * Управление командой: добавление маркетологов с правами «Только просмотр» или «Редактор кампаний».
* **12.3. Доступные действия:** Редактирование реквизитов, выпуск API токенов, приглашение сотрудников.
* **12.4. Логика работы:** Валидация ИНН через ФНС API. Синхронизация данных с ОРД.
* **12.5. Состояния:** `Saved`, `Unsaved changes warning`.
* **12.6. Ошибки:** Несовпадение КПП или БИК банка.
* **12.7. Ограничения:** Изменение ИНН заблокировано при наличии активных кампаний.
* **12.8. Взаимодействие:** ОРД API, DaData API, RBAC модуль.
