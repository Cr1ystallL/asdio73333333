# 🛡️ Полная спецификация административной панели (Admin & Ops Portal)

> [!IMPORTANT]
> Настоящий документ представляет собой детальное техническое задание для внутренней консоли управления платформой (для операторов модерации, сотрудников службы безопасности, финансовых контролеров и супер-администраторов). Каждый из 15 разделов расписан по стандарту промышленного проектирования.

---

## 1. Раздел: Dashboard (Командный центр платформы)
* **1.1. Назначение:** Мониторинг ключевых метрик здоровья платформы в реальном времени (ликвидность, оборот, загрузка очередей, алерты безопасности).
* **1.2. Элементы интерфейса:**
  * Виджеты верхнего уровня:
    * Суточный GMV и выручка платформы (рубли).
    * Число активных сабмитов на трекинге (`12 450`).
    * Очередь подозрительных видео (Risk Score $>70$): бейдж с красным счетчиком `[14]`.
    * Системный статус платежеспособности: `✅ Solvency Check: OK` (Остаток в банке покрывает все обязательства).
  * График нагрузки фоновых очередей BullMQ (опрос YouTube/VK в реальном времени).
  * Лента критических системных событий (Security Event Stream).
* **1.3. Доступные действия:** Переключение масштаба времени (1 час, 24 часа, неделя), ручной триггер аварийной остановки выплат (Emergency Stop).
* **1.4. Логика работы:** Запрос `GET /api/v1/admin/dashboard` с WebSocket-подпиской на критические события.
* **1.5. Состояния:** `Normal (все системы зеленые)`, `Warning (рост очереди модерации)`, `Critical Alert`.
* **1.6. Ошибки:** Потеря связи с сервером очередей Redis (красная плашка на весь экран).
* **1.7. Ограничения:** Доступ только для сотрудников с IP из белого списка.
* **1.8. Взаимодействие:** Все модули системы, Redis, PostgreSQL.

---

## 2. Раздел: Пользователи (Global User Directory)
* **2.1. Назначение:** Сквозной поиск и управление всеми учетными записями экосистемы.
* **2.2. Элементы интерфейса:**
  * Таблица пользователей: ID, Роль (`CLIPPER`, `ADVERTISER`, `MODERATOR`), Email / Telegram ID, Имя, Баланс, Trust Score, Статус (`ACTIVE`, `SUSPENDED`, `BANNED`), Дата регистрации.
  * Фильтры по ролям, диапазону балансов, наличию страйков.
* **2.3. Доступные действия:** Поиск по ИНН/Телефону/ID, переход в карточку пользователя, принудительный сброс сессий (Force Logout), блокировка.
* **2.4. Логика работы:** Пагинация по 50 записей с серверной фильтрацией.
* **2.5. Состояния:** `Table View`, `User Detail Drawer`.
* **2.6. Ошибки:** Пользователь не найден.
* **2.7. Ограничения:** Администратор не видит пароли (хранятся только хэши Argon2id).
* **2.8. Взаимодействие:** Модуль аутентификации, Ledger.

---

## 3. Раздел: Рекламодатели (Advertiser Management & KYC)
* **3.1. Назначение:** Проверка юридических лиц, верификация договоров и кредитных лимитов заказчиков.
* **3.2. Элементы интерфейса:** Таблица юридических лиц: Наименование, ИНН, Суммарный внесенный бюджет, Активные кампании, Статус ОРД интеграции, Наличие подписанного договора.
* **3.3. Доступные действия:** Аппрув юридических реквизитов, ручное выставление счетов, назначение персонального менеджера, изменение кредитного лимита.
* **3.4. Логика работы:** Сверка ИНН по базе ЕГРЮЛ через DaData.
* **3.5. Состояния:** `Pending Verification`, `Verified Partner`, `Blocked`.
* **3.6. Ошибки:** Недействительный ИНН или ликвидированное юрлицо.
* **3.7. Ограничения:** Право изменения реквизитов доступно только роли `LEGAL_OFFICER` или `SUPER_ADMIN`.
* **3.8. Взаимодействие:** B2B биллинг, ОРД модуль.

---

## 4. Раздел: Клипперы (Clipper CRM & Strikes)
* **4.1. Назначение:** Управление пулом создателей контента, история нарушений и учет выплат.
* **4.2. Элементы интерфейса:**
  * Таблица авторов: Telegram Username, Ранг (Bronze/Silver/Gold), Количество сданных роликов, Процент одобрения (Approval Rate), Счетчик страйков `[0 / 3]`.
  * Детальный профиль: привязанные соцсети, история выводов на карту по СБП, статус плательщика НПД в ФНС.
* **4.3. Доступные действия:** Выдача предупреждения (Strike), ручное повышение ранга (Promotion), блокировка вывода средств, амнистия страйка.
* **4.4. Логика работы:** При выставлении 3-го страйка система автоматически аннулирует сессию и замораживает доступный баланс.
* **4.5. Состояния:** `Good Standing`, `Warning (1-2 strikes)`, `Banned`.
* **4.6. Ошибки:** Попытка разбанить пользователя без указания причины в логе аудита.
* **4.7. Ограничения:** Каждое действие требует обязательного текстового комментария для аудита.
* **4.8. Взаимодействие:** Модуль антифрода, СБП шлюз.

---

## 5. Раздел: Кампании (Campaign Moderation & Status Control)
* **5.1. Назначение:** Модерация новых кампаний перед публикацией в общий каталог и контроль соблюдения законодательства РФ.
* **5.2. Элементы интерфейса:**
  * Очередь кампаний на премодерации (текст ТЗ, ссылки на исходники, категория).
  * Чек-лист проверки: соответствие 38-ФЗ о рекламе (нет ли запрещенных тематик, маркировка креатива).
  * Кнопки: `[ Одобрить и опубликовать в TMA ]`, `[ Отклонить с комментарием ]`.
* **5.3. Доступные действия:** Аппрув, отклонение, принудительная остановка активной кампании (Force Pause), ручное завершение и возврат остатка пула заказчику.
* **5.4. Логика работы:** После аппрува кампания переходит в `ACTIVE`, а бот отправляет пуш-рассылку в Telegram клипперам целевой категории.
* **5.5. Состояния:** `Pending Review`, `Active`, `Paused by Admin`, `Terminated`.
* **5.6. Ошибки:** Ошибка принудительного возврата депозита (если сумма заблокирована в незавершенных транзакциях).
* **5.7. Ограничения:** Кампании с бюджетом $>300\,000$ ₽ требуют подтверждения двумя администраторами (Four-Eyes Principle).
* **5.8. Взаимодействие:** Модуль кампаний, ОРД, бот-рассыльщик.

---

## 6. Раздел: Публикации (Submissions Audit & Video Player)
* **6.1. Назначение:** Мониторинг всех видеороликов, сданных в систему, со встроенным плеером и детальной телеметрией.
* **6.2. Элементы интерфейса:**
  * Инлайн-плеер шортсов и клипов.
  * Телеметрия ролика: начальные просмотры ($V_0$), текущие просмотры, динамика по часам, соотношение лайков к просмотрам (ER), список комментариев.
  * Проверка проверочного кода автора (`#clip_USERID` подсвечивается зеленым).
* **6.3. Доступные действия:** Принудительное одобрение сабмита, принудительное отклонение, исключение ролика из кампании.
* **6.4. Логика работы:** Администратор может вручную вызвать внеочередной опрос API соцсети для конкретного видео (`Force Refresh`).
* **6.5. Состояния:** `Tracking Live`, `Hold Active`, `Settled`.
* **6.6. Ошибки:** Ролик заблокирован соцсетью по авторским правам (отображается плашка DMCA / Copyright Takedown).
* **6.7. Ограничения:** Просмотр доступен без переходов на сторонние сайты.
* **6.8. Взаимодействие:** YouTube Data API, VK API.

---

## 7. Раздел: Модерация (Manual Review Queue)
* **7.1. Назначение:** Рабочий стол контент-модератора для ручной верификации спорных сабмитов.
* **7.2. Элементы интерфейса:**
  * Очередь тикетов модерации, отсортированная по времени поступления (FIFO).
  * Сравнение ТЗ кампании и реального содержания ролика.
  * Быстрые горячие клавиши: `[A]` — Одобрить, `[R]` — Отклонить, `[S]` — Пропустить (Skip).
* **7.3. Доступные действия:** Пакетный аппрув/отклонение сабмитов, отправка предупреждения клипперу.
* **7.4. Логика работы:** Модератор обрабатывает тикет, система фиксирует его ID и время проверки в `audit_logs`.
* **7.5. Состояния:** `Queue Empty (Индикатор: Все ролики проверены!)`, `Queue Busy`.
* **7.6. Ошибки:** Конфликт одновременного взятия тикета двумя модераторами (Optimistic Locking).
* **7.7. Ограничения:** Модератор обязан указать причину при отклонении ролика.
* **7.8. Взаимодействие:** Модуль сабмитов, уведомления.

---

## 8. Раздел: Антифрод (Risk Scoring & Anomaly Detection Desk)
* **8.1. Назначение:** Специализированное рабочее место службы безопасности для расследования скоординированных атак и накруток.
* **8.2. Элементы интерфейса:**
  * Таблица роликов с высоким индексом риска (`Risk Score >= 70`).
  * Детализация факторов риска: `ER: 0.08% (Критично)`, `Velocity: +40k за 15 мин`, `Duplicate Content pHash: 96%`.
  * Детектор кластеров (Cluster Analysis): выявление клипперов с одинаковыми IP, номерами телефонов или одним каналом накрутки.
* **8.3. Доступные действия:** Подтверждение фрода (с конфискацией средств), маркировка как ложное срабатывание (False Positive), блокировка всей сетки каналов.
* **8.4. Логика работы:** Автоматический алгоритм вычисляет веса рисков и формирует кластерные связи в графовой модели.
* **8.5. Состояния:** `Alerts Pending`, `Under Investigation`.
* **8.6. Ошибки:** Сбой генерации перцептивного хэша (pHash fallback на прямое сравнение метаданных).
* **8.7. Ограничения:** Доступ только для сотрудников службы безопасности (Risk Officers).
* **8.8. Взаимодействие:** Движок антифрода, Ledger (счета потерь).

---

## 9. Раздел: Финансы (Platform Solvency & Ledger Inspection)
* **9.1. Назначение:** Главный финансовый терминал компании; аудит целостности двойной записи и балансов.
* **9.2. Элементы интерфейса:**
  * Сводная ведомость счетов (Trial Balance):
    * Активы: `1000:BANK_CASH` (Остаток в ЮKassa + Т-Банк).
    * Обязательства: `2000:ADV_DEPOSITS`, `2100:CAMPAIGN_ESCROW`, `2200:CLIPPER_PENDING`, `2300:CLIPPER_AVAILABLE`.
    * Капитал/Доход: `3000:PLATFORM_REVENUE`, `4000:EXPENSES`.
  * Индикатор баланса: `Разница Дт - Кт = 0.00 ₽` (зеленый).
  * Поиск по журналу проводок (`ledger_entries`) по ID транзакции или пользователю.
* **9.3. Доступные действия:** Сверка с банковской выпиской, экспорт журнала проводок в 1С, создание балансирующей корректирующей проводки.
* **9.4. Логика работы:** Запрос агрегации балансов с проверкой системных инвариантов.
* **9.5. Состояния:** `Balanced`, `Discrepancy Detected (Критическая тревога)`.
* **9.6. Ошибки:** Обнаружение нарушения инварианта (немедленная блокировка всех внешних выплат).
* **9.7. Ограничения:** Прямое ручное редактирование строк в таблице `ledger_entries` технически заблокировано на уровне базы данных (запрет `UPDATE`/`DELETE` триггером).
* **9.8. Взаимодействие:** Ядро Ledger, банковские шлюзы.

---

## 10. Раздел: Выплаты (Payout Batches & SBP Approval)
* **10.1. Назначение:** Контроль и ручной аппрув реестров массовых выплат по СБП на карты клипперов.
* **10.2. Элементы интерфейса:**
  * Таблица сформированных заявок на вывод: Клиппер, Сумма, Номер СБП, Банк получателя, Статус самозанятого, Risk Score пользователя.
  * Пакетные действия: `[ Одобрить пачку выплат (42 заявки на 184 000 ₽) ]`, `[ Заморозить подозрительные ]`.
* **10.3. Доступные действия:** Ручной запуск батча выплат, отмена заявки с возвратом средств на доступный баланс клиппера.
* **10.4. Логика работы:** Заявки до 10 000 ₽ с низким риском выплачиваются автоматически. Заявки $>10\,000$ ₽ или от авторов с недавними предупреждениями требуют клика финансового контролера.
* **10.5. Состояния:** `Queue Pending`, `Processing Batch via SBP`, `Completed`.
* **10.6. Ошибки:** Недостаточно средств на расчетном счете выплатного банка (уведомление финотделу о необходимости пополнения мастер-счета).
* **10.7. Ограничения:** Выплаты проводятся строго в рублях РФ на карты банков РФ.
* **10.8. Взаимодействие:** Т-Бизнес API, СБП, ФНС (чеки).

---

## 11. Раздел: Комиссии (Platform Commission & Revenue Realization)
* **11.1. Назначение:** Управление процентными ставками комиссий платформы и признание выручки.
* **11.2. Элементы интерфейса:**
  * Текущая базовая ставка комиссии: `20.0%`.
  * Таблица специальных партнерских тарифов (индивидуальные ставки для крупных агентств: 12–16%).
  * Отчет о признанной выручке за текущий налоговый период (налоговая база УСН 6%).
* **11.3. Доступные действия:** Изменение глобальной комиссии (для новых кампаний), назначение персональной ставки рекламодателю.
* **11.4. Логика работы:** Расчет дохода платформы в момент завершения кампании по формуле $R = \text{Spent} \times 0.20$.
* **11.5. Состояния:** `Active Config`.
* **11.6. Ошибки:** Попытка установить комиссию менее себестоимости транзакций ($<4\%$).
* **11.7. Ограничения:** Доступно строго главному бухгалтеру и фаундерам.
* **11.8. Взаимодействие:** Ledger, модуль биллинга.

---

## 12. Раздел: Поддержка (Helpdesk & Support Desk)
* **12.1. Назначение:** Обработка входящих обращений пользователей из Telegram и Web-кабинетов.
* **12.2. Элементы интерфейса:**
  * Чат-панель с тикетами (диалоги с клипперами и рекламодателями).
  * Карточка пользователя рядом с чатом: баланс, текущие ролики, история тикетов.
  * База быстрых ответов (Canned Responses / Макросы).
* **12.3. Доступные действия:** Ответ в чат, передача тикета разработчикам, начисление компенсационного бонуса пользователю.
* **12.4. Логика работы:** Интеграция с Telegram Bot API: сообщения оператора моментально приходят клипперу в бота.
* **12.5. Состояния:** `Open`, `In Progress`, `Waiting Customer`, `Resolved`.
* **12.6. Ошибки:** Сбой доставки сообщения в Telegram (пользователь заблокировал бота).
* **12.7. Ограничения:** SLA первого ответа: до 15 минут в рабочее время.
* **12.8. Взаимодействие:** Telegram Bot API, CRM база.

---

## 13. Раздел: Жалобы и Апелляции (Disputes & Arbitration)
* **13.1. Назначение:** Официальный арбитраж спорных ситуаций между рекламодателем и клиппером.
* **13.2. Элементы интерфейса:**
  * Карточка спора:
    * Претензия рекламодателя: *«В ролике нет ссылки в закрепленном комментарии»*.
    * Доказательства клиппера: скриншот комментария и прямая ссылка.
    * Видеоролик во встроенном плеере.
  * Кнопки решения: `[ В пользу клиппера (Выплатить) ]`, `[ В пользу рекламодателя (Отклонить) ]`.
* **13.3. Доступные действия:** Принятие финального решения арбитража, вынесение предупреждения виновной стороне.
* **13.4. Логика работы:** Решение арбитра окончательное и не подлежит повторному обжалованию. Деньги списываются или возвращаются в соответствии с вердиктом.
* **13.5. Состояния:** `Pending Arbiter`, `Decision Rendered`.
* **13.6. Ошибки:** Попытка вынести вердикт без обоснования решения в протоколе.
* **13.7. Ограничения:** Регламент рассмотрения спора: до 24 часов.
* **13.8. Взаимодействие:** Ledger, модуль сабмитов, уведомления.

---

## 14. Раздел: Системные настройки (System Config & Feature Flags)
* **14.1. Назначение:** Управление конфигурацией платформы без перезагрузки бэкенд-серверов.
* **14.2. Элементы интерфейса:**
  * Переключатели функций (Feature Flags):
    * `ENABLE_VK_CLIPS`: [ВКЛ / ВЫКЛ].
    * `ENABLE_TIKTOK_SUBMISSIONS`: [ВКЛ / ВЫКЛ].
    * `INSTANT_CASHOUT_ENABLED`: [ВКЛ / ВЫКЛ].
  * Параметры антифрода: Минимальный порог ER (по умолчанию 1.5%), срок холда (по умолчанию 72 ч).
  * Параметры квот API: лимиты вызовов в сутки.
* **14.3. Доступные действия:** Изменение числовых полей, переключение тогла, сохранение конфигурации в Redis/БД.
* **14.4. Логика работы:** Бэкенд считывает конфигурацию из Redis с инвалидацией кэша через Pub/Sub события.
* **14.5. Состояния:** `Config Synced`.
* **14.6. Ошибки:** Ввод недопустимого диапазона значений (валидация JSON Schema).
* **14.7. Ограничения:** Доступно только роли `SUPER_ADMIN`.
* **14.8. Взаимодействие:** Redis, все сервисы бэкенда.

---

## 15. Раздел: Аудит действий (Audit Logs & Security Trail)
* **15.1. Назначение:** Неизменяемый журнал всех действий администраторов и модераторов для расследования инцидентов и предотвращения внутренних злоупотреблений.
* **15.2. Элементы интерфейса:**
  * Таблица аудита: Таймштамп, ID администратора, IP-адрес, Действие (`BAN_USER`, `APPROVE_SUBMISSION`, `MANUAL_PAYOUT`, `CHANGE_CONFIG`), Затронутый объект, Изменения (Diff: до/после).
  * Фильтр по типам критических действий.
* **15.3. Доступные действия:** Поиск по журналу, экспорт архива аудита.
* **15.4. Логика работы:** Запись ведется асинхронно через отдельный поток; таблица `audit_logs` защищена от удаления и модификации записей правами базы данных (Insert-Only).
* **15.5. Состояния:** `Continuous Stream`.
* **15.6. Ошибки:** Попытка очистить журнал аудита (генерирует критический алерт фаундерам).
* **15.7. Ограничения:** Записи хранятся бессрочно.
* **15.8. Взаимодействие:** Модуль безопасности, SIEM системы.
